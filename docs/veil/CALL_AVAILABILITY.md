# Call availability

The Privacy calls switch also publishes a calls preference of `NO` to each ready, active contact of the selected profile. This uses the existing encrypted contact-preferences update, including incognito connections; it does not change profile names or descriptions. The receiving app shows “This contact does not allow calls” in the Veil chat bar when the received calls preference is `NO`. This describes the contact's permission for this conversation, whether disabled globally or for this contact alone.

Re-enabling calls restores each contact's previous calls override, including an inherited default or an explicit refusal. Only the calls override changes. Ordinary contact-preference saves are also guarded while calls are off, so editing another feature cannot advertise calls as available. The original overrides are saved locally, separately for each host, profile and contact, and removed only after restoration succeeds. They are not included in chat database exports; an imported database with calls disabled may need its contact permissions enabled manually.

Reconciliation runs when the switch changes, chat starts, profile data loads and a contact connects. The native API restricts contact-preference writes to the active profile, so other profiles are reconciled when selected. The settings note states this limitation. Contacts that are not ready are handled when they connect. Failed writes retain their saved overrides and show an error with a retry action. Unexpected publication errors also leave chat startup available. Preference saves and reconciliation share the profile-switch mutex so one cannot overwrite the other during restoration. A successful write means the core accepted the update, not that the peer has received it; offline peers can temporarily display the previous permission. Incoming calls remain rejected locally while opted out.

Validation: Android common unit tests cover advertised refusal, disabling and restoring inherited and explicit permissions, preservation of unrelated preferences and conservative handling of corrupt snapshots, failed publication and restoration, retries after a restart, and idempotent reconciliation. On 2026-11-06, all 273 Veil Android common tests and the source-policy, strings, documentation, relay inventory, workflow and secret checks passed. Android common lint reported no new errors or warnings against a temporary baseline generated from the unchanged `bfa78cb70` tree, which already had 3,500 lint errors. The temporary baseline and its configuration are not committed. Two-device delivery, incognito delivery, offline delivery and the chat-bar layout still require device verification.
